# 02 - التحليل الهندسي للمهمة (Technical Analysis)

## 1. فهم المهمة والنطاق (Scope & Objectives)
المهمة الحالية تقتضي بناء الأساس البصري الشامل لنظام **Sub Tracker** وتأسيس حزمة السمات والرموز التصميمية ومراعاة متطلبات الوصولية الدولية (**WCAG 2.1 AA**) ودعم التدويل العربي أولاً (**RTL**).

هذه المهمة تقع بالكامل داخل **طبقة العرض ونواة الواجهة (`lib/core/theme/` و `lib/features/subscriptions/presentation/`)**، ولا تمس طبقة الدومين (`domain/`) أو طبقة البيانات (`data/`)، التزاماً بمبدأ العزل المعماري الصارم.

---

## 2. تحليل المتطلبات الوظيفية وغير الوظيفية وقصص المستخدم

### أ. المتطلب غير الوظيفي `NFR-04` (الوصولية وسهولة الاستخدام):
- نسبة تباين لا تقل عن $4.5:1$ للنصوص العادية، و $3:1$ للنصوص الكبيرة والعناصر التفاعلية.
- دعم الوضعين الفاتح (Light Mode) والداكن (Dark Mode).
- ألا تقل مساحة أي عنصر تفاعلي أو زر عن $48 \times 48$ نقطة منطقية (Logical Pixels).
- دعم تكبير الخط إلى 200% (`TextScaler.linear(2.0)`) دون انكسار التخطيط أو تداخل النصوص.

### ب. المتطلب غير الوظيفي `NFR-08` (التدويل ودعم العربية أولاً):
- دعم الاتجاه من اليمين إلى اليسار (**RTL**) في كافة المحاذاة والرموز والأيقونات الاتجاهية.
- ضبط الخط العربي ومقاييس ارتفاع السطر (Line-height) لتجنب قص الحروف ذات العلامات العلوية أو السفلية.
- عزل النصوص عن الكود لمنع القيم الثابتة المباشرة.

### ج. قصة المستخدم `US-40` وحالات الحافة:
- **`[EC-40-1]` التخطيط المتجاوب:** تعريف مسافات وهوامش متدرجة تتلاءم مع أحجام الشاشات المختلفة.
- **`[EC-40-3]` دعم عمى الألوان:** اقتران الألوان الدلالية (نجاح، تحذير، خطأ، تأخير) برموز نصية أو أيقونية محددة في نظام التصميم حتى لا تكون المعلومة معتمدة على اللون منفرداً.

## 3. بنية الرموز التصميمية المعتمدة (Three-Layer Token Architecture)

وفق أفضل الممارسات الهندسية للمهارة `design-system`، يتم بناء الرموز على ثلاث طبقات:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Primitive Tokens (قيم خام مجردة)                         │
│    لوحة الألوان الأساسية، شبكة المسافات (4/8/16/24/32/48)،  │
│    أنصاف الأقطار (Radius)، أحجام وأوزان الخطوط.             │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ 2. Semantic Tokens (معانٍ واستخدامات دلالية)                │
│    الألوان بحسب الغرض: Background, Surface, Primary,        │
│    TextPrimary, TextSecondary, Error, Warning, Success.     │
│    (تتغير قيمتها بين السمة الفاتحة والداكنة).               │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ 3. Component Tokens & Themes (تطبيق على مكونات Flutter)     │
│    CardTheme, AppBarTheme, ElevatedButtonTheme,             │
│    InputDecorationTheme, TextTheme, DialogTheme.            │
└─────────────────────────────────────────────────────────────┘
```

## 4. التحليل الرياضي لنسب التباين (Contrast Ratio Analysis)

تُحسب نسبة التباين وفق معادلة WCAG 2.1:
$$\text{Contrast Ratio} = \frac{L_1 + 0.05}{L_2 + 0.05}$$
حيث $L_1$ هو السطوع النسبي (Relative Luminance) للون الأفتح، و $L_2$ للون الأغمق.

### لوحة الألوان المقترحة والمختبرة:
1. **السمة الفاتحة (Light Theme):**
   - الخلفية الأساسية (`Background`): `#F8FAFC` (Slate 50)
   - السطح (`Surface` / Cards): `#FFFFFF` (White)
   - النص الأساسي (`TextPrimary`): `#0F172A` (Slate 900) $\rightarrow$ تباين مع السطح **$18.5:1$** (يجتاز $4.5:1$ بجدارة).
   - النص الثانوي (`TextSecondary`): `#475569` (Slate 600) $\rightarrow$ تباين مع السطح **$5.9:1$** (يجتاز $4.5:1$).
   - اللون الأساسي (`Primary Brand`): `#4F46E5` (Indigo 600) $\rightarrow$ تباين مع الأبيض **$5.4:1$**.
   - خطأ (`Error`): `#DC2626` (Red 600) $\rightarrow$ تباين **$5.1:1$**.
2. **السمة الداكنة (Dark Theme):**
   - الخلفية الأساسية (`Background`): `#0F172A` (Slate 900)
   - السطح (`Surface` / Cards): `#1E293B` (Slate 800)
   - النص الأساسي (`TextPrimary`): `#F8FAFC` (Slate 50) $\rightarrow$ تباين مع السطح **$15.2:1$**.
   - النص الثانوي (`TextSecondary`): `#94A3B8` (Slate 400) $\rightarrow$ تباين مع السطح **$5.8:1$**.
   - اللون الأساسي (`Primary Brand`): `#818CF8` (Indigo 400) $\rightarrow$ تباين مع السطح الداكن **$6.2:1$**.
   - خطأ (`Error`): `#F87171` (Red 400) $\rightarrow$ تباين **$5.9:1$**.

## 5. تحليل مساحات اللمس والوصولية (Touch Target Analysis)
- وضع حد أدنى لأي عنصر تفاعلي أو زر: `minTouchTarget = 48.0` نقطة منطقية (`MaterialTapTargetSize.padded`).
- أزرار الإجراءات السريعة وحقول الإدخال تلتزم بارتفاع لا يقل عن `48.0` أو `56.0` نقطة.

## 6. الملفات المتأثرة والمقرر إنشاؤها
- **ملفات الكود في المشروع (`lib/core/theme/`):**
  1. `lib/core/theme/app_colors.dart` (الألوان الخام والدلالية الفاتحة والداكنة)

  2. `test/unit/core/theme/app_theme_test.dart` (اختبار خصائص السمتين الفاتحة والداكنة ومطابقة الألوان ومساحات اللمس)
  3. `test/widget/core/theme/theme_accessibility_test.dart` (اختبار نسب التباين البرمجية $\ge 4.5:1$، واختبار تكبير الخط 200%، واتجاه RTL)

## 7. المخاطر والاحتياطات (Risks & Mitigations)
- **الخطر:** انكسار النصوص أو تداخل عناصر الواجهة عند تكبير الخط إلى 200%.
  - **الحل:** اعتماد ارتفاع سطر مرن (`height` ملائم) واستخدام `Flexible` أو `Wrap` أو `SingleChildScrollView` مع بطاقات قابلة للتمدد وتجنب الارتفاعات الثابتة الصارمة للنصوص (`fixed heights`).
- **الخطر:** عدم وضوح النصوص في الوضع الداكن.
  - **الحل:** استخدام نغمات ألوان سطوع مدروسة ومطابقة لمعادلة تباين WCAG 2.1 واختبارها باختبار وحدة آلي حاسم.
