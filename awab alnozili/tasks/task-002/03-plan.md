# 03 - خطة التنفيذ خطوة بخطوة (Implementation Plan)

## 1. أهداف الخطة
بناء طبقة العرض (`presentation`) للاشتراكات في `lib/features/subscriptions/presentation/` مع تغطية شاملة للشاشات والمكونات والحالات الأربع واختبارها عبر اختبارات الواجهة (`Widget Tests`) بنسبة نجاح 100% وخلو تام من التحذيرات أو الشاشات البيضاء.

---

## 2. مراحل التنفيذ التفصيلية

### المرحلة 1: نماذج الحالة وعقود العرض (`presentation/state/`)
1. إنشاء الصنف المختوم `SubscriptionsViewState` لدعم الحالات الأربع بدقة تامة:
   - `SubscriptionsLoading`: حالة التحميل الأولي أو التحديث.
   - `SubscriptionsEmpty`: حالة عدم وجود اشتراكات مع رسالة استرشادية.
   - `SubscriptionsData`: حالة توفر البيانات مع قائمة الاشتراكات وبيانات الفئات والملخص المالي.
   - `SubscriptionsError`: حالة حدوث خطأ مع رسالة الخطأ ودالة الاستدعاء لإعادة المحاولة.
2. إنشاء كائن القيمة التحليلي للوحة الملخص `ExpenseSummary`:
   - حساب المكافئ الشهري وفق قواعد `BR-07` لكل دورية (شهرية: القيمة نفسها، سنوية: القيمة / 12، أسبوعية: القيمة $\times 52 / 12$، مخصصة: القيمة $\times 30.4375 / \text{days}$).
   - تجميع الإجماليات متعددة العملات بشكل مستقل (`Map<String, Money> totalsByCurrency`).
   - حساب إجمالي الاشتراكات النشطة والتجارب المجانية.
3. إنشاء `SubscriptionsController` (`ChangeNotifier` / `ValueNotifier`):
   - يتيح إدارة حالة الشاشة بسلاسة وحقنها للاختبارات.

### المرحلة 2: المنسقات والأدوات المساعدة (`presentation/formatters/`)
1. إنشاء `SubscriptionFormatters`:
   - تنسيق مبالغ العملات مع الفواصل الآلافية ورموز العملة.
   - تنسيق النصوص الزمنية للدوريات بالعربية ("شهرياً", "سنوياً", "أسبوعياً", "كل X يوم").
   - تنسيق حالات الاستحقاق ("يستحق اليوم", "متبقي X يوم", "متأخر منذ X يوم").

### المرحلة 3: المكونات البصرية المشتركة والحالات الأربع (`presentation/widgets/`)
1. **`empty_state_view.dart`:**
   - تصميم واجهة متكاملة للحالة الفارغة (أيقونة، عنوان، نص فرعي، وزر تفاعلي بحد أدنى للمس $48\times 48$).
2. **`error_state_view.dart`:**
   - تصميم واجهة مخصصة للأخطاء (أيقونة تحذيرية، رسالة شارحة بالعربية، وزر «إعادة المحاولة»).
3. **`loading_shimmer_view.dart`:**
   - محاكاة هيكلية للبطاقات والملخص بدون شاشة بيضاء باستخدام ألوان متوافقة مع السمة الحالية.
4. **`subscription_card.dart`:**
   - بطاقة متناسقة تستخدم `AppTokens`، تعرض الاسم مع الاقتطاع الآمن، السعر، الدورية، شارة الفئة، وحالة الاستحقاق الملونة والنصية.
   - تمييز حالات الاستحقاق الحرجة ($\le 3$ أيام) والمتأخرة والتجارب المجانية.
5. **`summary_dashboard.dart`:**
   - لوحة إحصائية مميزة في أعلى الشاشة الرئيسية تعرض المكافئ الشهري، عدد الاشتراكات، والعملات المنفصلة.

### المرحلة 4: الشاشات الرئيسية (`presentation/screens/`)
1. **`home_screen.dart`:**
   - الشاشة الرئيسية للتطبيق: تربط `SubscriptionsController` بـ `SubscriptionsViewState`.
   - التبديل الآلي بين الحالات الأربع (`Loading`, `Empty`, `Data`, `Error`).
   - سحب للتحديث (`RefreshIndicator`) وزر إضافة عائم (`FloatingActionButton`).
2. **`add_edit_subscription_screen.dart`:**
   - نموذج إضافة وتعديل الاشتراك بجميع الحقول والقواعد المحددة في `US-01` و `US-07`.
   - التحقق الدفاعي اللحظي بواسطة `SubscriptionValidator`.
   - الحالات الأربع: التحميل أثناء الحفظ، عرض الحقول، الأخطاء الموضعية أسفل الحقول، وحالة الفراغ أو الفشل.
   - نافذة تأكيد الإلغاء لمنع فقد البيانات غير المحفوظة.

### المرحلة 5: منظومة اختبارات الواجهة (`test/widget/presentation/`)
1. `home_screen_test.dart`: اختبار الحالات الأربع والتفاعل وزر إعادة المحاولة.
2. `subscription_card_test.dart`: اختبار عرض البطاقة والحالات الحرجة والأيام المتبقية وحجم اللمس.
3. `summary_dashboard_test.dart`: اختبار دقة الحسابات، فصل العملات المتعددة، وتكبير الخط 200%.
4. `add_edit_subscription_screen_test.dart`: اختبار التعبئة، التحقق الدفاعي، التبديل بين الدوريات، وزر الحفظ.
