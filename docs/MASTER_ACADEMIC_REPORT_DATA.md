# القسم الأول: الهوية الأكاديمية وفلسفة النظام

### 1-1 بيان المشكلة (Problem Statement)
في العصر الرقمي الحديث، يعاني الأفراد وأصحاب المشاريع الناشئة من ظاهرة **«تراكم الالتزامات الصامت» (Subscription Creep)**؛ حيث تتعدد الالتزامات المالية المتكررة (فواتير كهرباء، مياه، اتصالات، إنترنت منزلي، إيجار سكن، رخص برمجية، أقساط قروض، اشتراكات ترفيهية ومهنية) على مدار الشهر بتواريخ استحقاق متفرقة، وبدويات متباينة (أسبوعية، شهرية، نصف سنوية، سنوية، مخصصة بالأيام)، وبعملات متعددة (ريال يمني، دولار أمريكي، ريال سعودي، وغيرها). هذا التشتت ينجم عنه:
1. **النزيف المالي غير المحسوب:** استمرار استنزاف الأموال في التزامات مهملة أو غير مستخدمة.
2. **غرامات التأخير وانقطاع الخدمات الحيوية:** بسبب النسيان والاعتماد على الذاكرة البشرية المجردة.
3. **انتهاك الخصوصية الصارخ في الحلول السحابية:** معظم التطبيقات التجارية تشترط إنشاء حسابات سحابية ورفع السجلات المالية الشخصية الحساسة إلى خوادم مركزية تتعرض للاختراق أو الاستغلال الإعلاني.

### 1-2 الحل المقترح في مشروع Sub Tracker
بناء نظام إدارة محاسبية شخصية متقدم وفق فلسفة **«الخصوصية أولاً دون اتصال بالإنترنت» (Offline-First Privacy-by-Design)**. يقوم النظام على المبادئ التالية:
- **صفر صلاحيات إنترنت:** حظر وإزالة صلاحية `android.permission.INTERNET` نهائياً من ملف المانيفست، مما يجعل تسريب أي بايت من البيانات مستحيلاً فيزيائياً وبرمجياً.
- **التخزين العلائقي المحلي المحكم:** استخدام محرك SQLite عبر مكتبة Drift بدلاً من التخزين السطحي للمفاتيح والقيم، لتوفير معاملات ذرية (ACID Transactions) متكاملة.
- **التأمين المحلي الشامل برمز PIN:** قفل التطبيق محلياً بتشفير SHA-256 مع ملح محلي وحظر هجمات التخمين بعد 5 محاولات.
- **الإشعارات المجدولة محلياً:** تنبيهات دقيقة قبل الاستحقاق بيوم تعمل بالكامل على معالج الهاتف ودون الحاجة لأي خادم وسيط.
- **التحليل المالي الدقيق:** عزل العملات، وحساب المكافئات الشهرية والسنوية، واستعراض التوزيع الفئوي عبر رسوم بيانية تفاعلية من مكتبة `fl_chart`.

# القسم الثاني: سجل كافة الأوامر المنفذة من البداية وحتى النهاية مع شرح علة كل أمر

فيما يلي التوثيق الشامل لكافة الأوامر البرمجية والطرفية التي نُفذت في المشروع خطوة بخطوة، مع توضيح العلة الهندسية (Rationale) والنتيجة المحققة لكل أمر:

### 2-1 مرحلة التأسيس وهيكل المشروع (Scaffolding & Architecture)
1. **إنشاء مشروع فلاتر:**
   ```bash
   flutter create --org com.subtracker --project-name sub_tracker .
   ```
   - **العلة الهندسية:** تهيئة بيئة Flutter الرسمية وتحديد معرف الحزمة الفريد (Package Identifier) المناسب لنظام أندرويد.
   - **النتيجة:** توليد الهيكل الأولي للمجلدات ومشاريع المنصات (Android, Web, Windows).

2. **تهيئة مستودع Git واعتماد نموذج الفروع (Gitflow):**
   ```bash
   git init
   git branch -M main
   git checkout -b develop
   ```
   - **العلة الهندسية:** حظر التطوير المباشر على الفرع الرئيسي `main`، وتأسيس فرع التطوير المستمر `develop` لربطه بنظام التكامل المستمر (CI).

3. **ضبط قواعد التجاهل الصارمة في `.gitignore`:**
   - **العلة الهندسية:** استثناء مجلدات البناء `build/`، وملفات الكاش `.dart_tool/`، والملفات المؤقتة، لمنع تضخم المستودع.
   - **الاستثناء المعتمد لاحقاً:** إضافة `!releases/` لتتبع الحزم الرسمية المخصصة للتوزيع فقط.

### 2-2 مرحلة إدارة الحزم والمكتبات الخارجية (Dependencies Management)
1. **تثبيت محرك قواعد البيانات المحلي:**
   ```bash
   flutter pub add drift sqlite3_flutter_libs path_provider path
   flutter pub add --dev drift_dev build_runner
   ```
   - **العلة الهندسية:** اختيار `drift` بوصفها أقوى وأسرع مكتبة ORM لـ SQLite في بيئة Dart؛ لأنها تضمن Type-Safety بنسبة 100%، وتوفر تدفقات تفاعلية لحظية (Reactive Streams)، مع دعم المعاملات الذرية وفهارس الاستعلام السريعة.

2. **تثبيت حزم الرسوم البيانية والتوطين والتواريخ:**
   ```bash
   flutter pub add fl_chart intl
   ```
   - **العلة الهندسية:** حزمة `fl_chart` لإنشاء الرسوم البيانية الدائرية والشريطية التفاعلية مع دعم اللمس، وحزمة `intl` لدعم تنسيق التواريخ والأرقام والعملات باللغة العربية.

3. **تثبيت حزم الإشعارات والتشفير:**
   ```bash
   flutter pub add flutter_local_notifications timezone crypto
   ```
   - **العلة الهندسية:** مكتبة `flutter_local_notifications` مع `timezone` لجدولة التنبيهات المسبقة على مستوى نظام التشغيل دون خوادم سحابية، ومكتبة `crypto` لتطبيق خوارزمية التشفير المحلي SHA-256 لتأمين رمز PIN.

4. **تثبيت حزم الاختبارات ومحاكاة السلوك:**
   ```bash
   flutter pub add --dev test test_api mockito
   ```
   - **العلة الهندسية:** توفير البنية الأساسية لهرم الاختبارات وكتابة عقود الاختبارات لوحدات الدومين والواجهات.

### 3-1 الملف الأول: [`codeguaid.md`](file:///e:/%D9%85%D8%B3%D8%AA%D9%88%D8%A6%20%D8%B1%D8%A7%D8%A8%D8%B9/Mindx/Sub%20Tracker/.agents/rules/codeguaid.md) (دستور التشغيل البرمجي)

#### كيف كُتب وما علة وجوده؟
كُتب ليحل معضلة شائعة في الذكاء الاصطناعي: «الميل إلى الارتجال، واقتراح مكتبات خارجية عشوائية، وتجاوز حدود الطبقات المعمارية». وُضع هذا الملف ليكون الحاكم الأعلى (Hard Constraint)، بحيث إذا تعارض طلب المستخدم مع قاعدة في هذا الملف، يلتزم الوكيل برفض الطلب، وذكر رقم القاعدة، واقتراح بديل هندسي سليم.
- **حل مشكلة الحجم:** كانت بيئة Antigravity تُظهر خطأً باللون الأحمر لتجاوز الملف 12,000 حرف (وصل إلى 17,513 حرفاً). قمنا بإعادة صياغته بأسلوب **«التكثيف الهندسي»**، حيث ضغطناه إلى **9,165 حرفاً** مع الحفاظ على كل حرف من القواعد الصارمة.

#### محتوياته بالتفصيل:
1. **هوية الوكيل (Agent Identity):** تعريفه بأنه مهندس البرمجيات الرئيسي (Principal Software Engineer) لنظام Sub Tracker، الملزم بحماية المعمارية وربط كل تعديل برقم متطلب صريح.
2. **حلقة التنفيذ الإلزامية ذات الخطوات السبع (The 7-Step Mandatory Loop):**
   - **Step 1 - Ground:** العودة وقراءة وثيقة المتطلبات `SRS.md` وقصص المستخدم `USER_STORIES.md`.
   - **Step 2 - Skill Selection:** إعلان المهارات المستند إليها في بداية كل رد.
   - **Step 3 - Plan:** تخطيط مسار التبعية الداخلية وعقد الاختبار قبل لمس الكود.
   - **Step 4 - Test Contract Gate:** حظر كتابة كود التنفيذ قبل كتابة اختبار يسقط أولاً (Red-Green-Refactor).
   - **Step 5 - Implement:** كتابة الكود بأصغر زيادة coherent increment دون ترك TODOs أو دوال ناقصة.
   - **Step 6 - Verify:** تشغيل الثالوث الفاحص (تنسيق، تحليل، اختبارات).
   - **Step 7 - Self-Audit:** قائمة تدقيق من 7 أسئلة ذاتية قبل تسليم العمل.
3. **تطبيق مبادئ SOLID الخمسة برمجياً:**
   - **SRP:** مسؤولية واحدة لكل ملف؛ عزل كائنات القيمة في ملفات منفصلة عن الكيانات.
   - **OCP:** إضافة أنواع التزامات جديدة عبر Enum والواجهات المجردة دون كسر القديم.
   - **LSP:** تطابق نتائج المستودعات البديلة (Fakes) مع المستودعات الحقيقية.
   - **ISP:** تفكيك الواجهات الكبيرة؛ فصل `PaymentRepository` عن `SubscriptionRepository`.
   - **DIP:** اعتماد طبقة العرض والبيانات على واجهات الدومين المجردة، دون أن يعرف الدومين شيئاً عنهما.
4. **نقاء طبقة الدومين (Domain Purity 100%):** منع استيراد حزم `flutter/*` أو `drift/*` نهائياً في مجلد `domain/`.
5. **الأنماط المعمارية المعتمدة برمجياً:**
   - كود Dart النقي لتشفير PIN بـ SHA-256 مع الملح المحلي.
   - كود المعاملات الذرية وسجل الأسعار.
   - كود الصياغة النحوية العربية للأعداد والمعدود.

# القسم السابع: المعمارية النظيفة (Clean Architecture) ونموذج البيانات المحلي

### 7-1 فلسفة الطبقات الثلاث وتدفق التبعية
يلتزم المشروع بهيكل المعمارية النظيفة ذي الاتجاه الواحد نحو الداخل:
- **طبقة الدومين (`lib/features/subscriptions/domain/`):** كود Dart نقي بنسبة 100%. خالية تماماً من استيراد Flutter أو Drift أو منصات النظام. تضم الكيانات (`Subscription`, `Category`, `PaymentRecord`)، وكائنات القيمة المحمية (`Money`, `DueDate`, `PinCode`)، وواجهات المستودعات التجريدية، وحالات الاستخدام المنفردة.
- **طبقة البيانات (`lib/features/subscriptions/data/`):** تحتكر التعامل مع قاعدة بيانات SQLite ومكتبة Drift. تضم تعريفات الجداول، وكائنات الوصول DAOs، ونماذج التحويل (Models)، ومصادر البيانات، وتنفيذ المستودعات مع عزل وتحويل استثناءات SQLite إلى كائنات إخفاق Failures بالدومين.
- **طبقة العرض (`lib/features/subscriptions/presentation/`):** تعرض الواجهات وتستقبل مدخلات المستخدم. تضم الشاشات، والويدجات، ومتحكمات الحالة بنمط MVVM، والمنسقات اللغوية، وتستورد طبقة الدومين حصراً.

### 7-2 نموذج جداول SQLite عبر Drift
1. **جدول الاشتراكات والالتزامات (`subscriptions`):**
   - الحقول: `id` (رقمي تلقائي)، `name` (نص مشذب ومحمي من التكرار)، `amount_minor` (قيمة صحيحة بالسنتات)، `currency` (رمز العملة ISO)، `billing_cycle` (نوع الدورية)، `custom_interval_days` (في حال الدورية المخصصة)، `start_date` (تاريخ البدء المرجعي لمنع الانزياح)، `due_date` (تاريخ الاستحقاق المحسوب)، `category_id` (مفتاح أجنبي مرتبط بالفئات)، `status` (نشط، مؤرشف، في السلة)، `obligation_type` (اشتراك، فاتورة، إيجار، أخرى).
2. **جدول الفئات (`categories`):**
   - الحقول: `id`، `name_ar`، `icon_name`، `color_value`، `is_system_default`.
3. **جدول سجل الأسعار (`price_history`):**
   - الحقول: `id`، `subscription_id` (مرتبط بـ CASCADE)، `old_amount_minor`، `new_amount_minor`، `change_date`، `reason`.
4. **جدول سجل الدفعات (`payment_records`):**
   - الحقول: `id`، `subscription_id`، `paid_amount_minor`، `paid_date`، `notes`.
5. **جدول الإعدادات العامة (`settings`):**
   - الحقول: `key` (مفتاح فريد)، `value` (قيمة نصية)، لحفظ حالة PIN المشفرة، والعملة الافتراضية، والسمة.

# القسم الثامن: الأمان، الإشعارات، والتحليلات البيانية

1. **الأمان المحلي المشفر (Local SHA-256 PIN Security):**
   - لا يتم تخزين أرقام PIN الأربعة أبداً كنصوص صريحة.
   - عند إنشاء الرمز، يتم خلطه بملح محلي فريد (Salt) وتوليد تجزئة SHA-256 عبر مكتبة `crypto`.
   - يتم تخزين التجزئة في جدول الإعدادات. عند فتح التطبيق في `main.dart`، تعترض بوابة `PinLockScreen` الإقلاع وتطلب الرمز لمطابقة التجزئة.
   - حماية ضد هجمات القوة الغاشمة (Brute-Force Attack): بعد 5 محاولات إدخال متتالية خاطئة، يُقفل النظام ويبدأ مؤقت حظر تفاعلي تنازلي لمدة 30 ثانية.

2. **خدمة الإشعارات المحلية (Local Notifications Engine):**
   - مبنية داخل فئة معزولة `NotificationService` باستخدام `flutter_local_notifications` و `timezone`.
   - تدعم التوافق الشامل مع أندرويد من إصدار 5.0 القديم وحتى 15+ الحديث عبر مكتبة core library desugaring.
   - ضبط أذونات المنبه الدقيق `SCHEDULE_EXACT_ALARM`، ومستقبلات إعادة تشغيل الهاتف `RECEIVE_BOOT_COMPLETED` لضمان بقاء التنبيهات المجدولة فعالة حتى بعد إطفاء وتشغيل الهاتف.
   - إلغاء وإعادة جدولة التنبيه تلقائياً عند تعديل تاريخ الالتزام أو سداده أو حذفه.

3. **التحليلات البيانية ورسوم `fl_chart`:**
   - رسم بياني دائري (`CategoryPieChart`): يوضح حصة كل فئة إنفاق مع تفاعل لمسي ناعم (Hover/Touch Interaction) وتكبير القطاع المختار.
   - رسم بياني شريطي (`MonthlyComparisonChart`): يعرض مقارنة ثلاثية بصرية (المستحق، المسدد، المتبقي) للشهر الجاري.
