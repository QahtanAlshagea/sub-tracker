## 2. نص المتطلب الوظيفي (Functional Requirements Trace)
تستند المهمة إلى متطلبات `docs/SRS.md` وقصص المستخدم في `docs/USER_STORIES.md`:
- **FR-01 إلى FR-07:** العمليات الأساسية على الاشتراكات (إضافة، تعديل، حذف بمرحلتين: سلة المحذوفات ثم الحذف النهائي، الأرشفة، والاستعادة).
- **FR-08:** التجديد التلقائي للاشتراك بعد تسجيل الدفع أو انقضاء الموعد.
- **FR-11 إلى FR-14:** إدارة الفئات (إضافة، تعديل، حذف، إعادة تعيين الاشتراكات لفئة أخرى).
- **FR-20:** الاستعلامات المفلترة بحسب الحالة، الفئة، والبحث النصي، وبث التحديثات التفاعلية (Streams).
- **قصص المستخدم المغطاة:** `US-01`, `US-06`, `US-07`, `US-08`, `US-09`, `US-10`, `US-12`, `US-13`, `US-14`, `US-15`.

## 3. قائمة معايير القبول والاكتمال (Acceptance Criteria)
1. كتابة الواجهات المجردة `SubscriptionRepository` و `CategoryRepository` بنقاء كامل في الدومين.
2. بناء 16 حالة استخدام (`UseCase`) تغطي كافة العمليات الفردية والجماعية.
3. اعتماد النمط الوظيفي `Result<T>` (`Success` أو `Error`) لمنع تسرب أي استثناء عبر حدود الدومين.
4. تغطية حالات الاستخدام باختبارات وحدة تستخدم بدائل مولدة (Mocks).
5. اجتياز 34 اختبار وحدة مخصص لـ C-09 بنسبة نجاح 100%.
