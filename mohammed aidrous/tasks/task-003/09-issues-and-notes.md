# 09-issues-and-notes.md — الملاحظات والقرارات المعمارية
## المهمة: C-09 — واجهات المستودعات وحالات الاستخدام
### المهندس: محمد العيدروس (Mohammed Al-Aidrous)

---

## 1. القرارات المعمارية التي تم اتخاذها
1. **رفض وضع حالات الاستخدام كدوال عامة أو داخل الكيانات:**
   - تم رفض مقترح وضع العمليات كدوال عامة حرة (top-level functions) أو حشرها داخل كائن `Subscription`، والتأكيد على بناء كلاس مستقل لكل UseCase تحقيقاً لمبدأ المسؤولية الواحدة (SRP) وسهولة حقن التبعيات والاختبار المستقل.
2. **اعتماد النمط الوظيفي `Result<T>`:**
   - تم اعتماد `Result.success` و `Result.error` لمنع تسريب استثناءات التخزين أو الشبكة عبر حدود المستودع، بحيث تتعامل طبقة العرض مع نتائج آمنة ومعلومة.
3. **حماية الفئة الافتراضية للنظام:**
   - تم فرض قيد يمنع حذف الفئة النظامية "غير مصنّف" داخل `DeleteCategoryUseCase` لضمان عدم وجود اشتراكات يتيمة دون فئة في النظام.

---

## 2. الدروس المستفادة والتوصيات
- إن الفصل بين استعلامات القراءة (Watch Streams) وعمليات التعديل (Commands) يمهد الطريق لتطبيق نمط CQRS بشكل طبيعي وسلس دون تعقيد إضافي.
