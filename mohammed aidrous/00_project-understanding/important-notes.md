# الملاحظات الحرجة والديون التقنية والحدود الصارمة (Important Notes)
## المهندس: محمد العيدروس (Mohammed Al-Aidrous)

---

## 1. التبعيات والحدود المعمارية الحساسة

1. **نقاء طبقة الدومين (Zero-Tolerance Domain Purity):**
   - يُمنع تماماً استيراد أي مكتبة من خارج Dart النقي داخل `lib/features/*/domain/` أو `lib/core/usecase/` أو `lib/core/error/`.
   - يتم التحقق من هذا الشرط تلقائياً في سير عمل GitHub Actions، وأي مخالفة توقف البناء فوراً.
2. **استقلالية الملفات ومبدأ المسؤولية الواحدة (SRP):**
   - كل صنف (Entity, ValueObject, Failure, UseCase, Repository Contract) يجب أن يكون في ملف منفصل ومستقل.
   - يُمنع دمج واجهة المستودع مع تنفيذه، أو دمج الـ UseCase مع الـ State، أو دمج الـ Validator مع الـ Entity.
3. **عقد معالجة الأخطاء (Error Handling Contract):**
   - يُمنع إطلاق الاستثناءات (`throw`) للتعامل مع الأخطاء المتوقعة.
   - تستخدم كافة الـ UseCases النمط الوظيفي `Result<T>` (`Success<T>` أو `Error<T>`).
   - تتولى طبقة البيانات تحويل كافة استثناءات التخزين إلى كائنات `Failure` عند حدود المستودع.

---

## 2. إدارة Git والفروع ومراجعة الكود

1. **الفروع الرئيسية المحمية:**
   - الفرعان `main` و `develop` محميان بصرامة.
   - يُمنع الدفع المباشر (`direct push`) إليهما إطلاقاً.
   - لا يتم الدمج إلا عبر طلب دمج (Pull Request) معتمد يجتاز كافة فحوصات CI الآلية.
2. **فروع الميزات (Feature Branches):**
   - يتم العمل دائماً في فروع ميزات مخصصة للمهمة (مثل: `feature/c-07-aidrous-domain-entities`).
3. **توزيع المسؤوليات وملاك الشيفرة (CODEOWNERS):**
   - **محمد العيدروس:** طبقة الدومين، الكيانات، التحقق، حالات الاستخدام، المحرك المالي، والواجهات.
   - **قحطان الشاجع:** المعمارية والحوكمة والتوثيق وسير العمل.
   - **أواب النزيلي:** الدومين ونظام التصميم والواجهات.
   - **مشعل حاجب:** التخزين المحلي وقواعد البيانات والجداول والـ DAOs.
   - **محمد العواضي:** ضمان الجودة ومنظومة الاختبارات وحالات الحافة.
